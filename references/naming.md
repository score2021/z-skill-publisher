# 名称、个人前缀与引用一致性

确定或修改名称、生成 UI metadata、写安装说明及验证名称时读取。此文件是详细命名规则的唯一来源；其他文档只保留必要摘要与测试场景。

## 先确定是否适用默认前缀

| 情况 | 决定 |
| --- | --- |
| 改进既有 skill，未要求改名 | 保留原名；本 skill 保持 `z-skill-publisher` |
| 新建，未指定名称 | 取简短用途名，默认 `z-<用途>` |
| 新建，只给基础名，未要求精确保留 | 添加一次 `z-` |
| 新建，已带 `z-` | 保留一个前缀，不产生 `z-z-…` |
| 明确指定完整名称并要求原样保留 | 名称有效就尊重，包括不以 `z-` 开头的名称；无效则说明并给规范化建议 |

`z-` 方便输入前缀筛选个人技能、区别官方/插件技能，是标准兼容的个人偏好，不是官方强制。默认规则本身不授权迁移既有名称。

## 格式与规范化

所有最终名称用小写字母、数字和单连字符，主体非空、首尾无连字符、无连续连字符，总长度最多 64。通用检查使用 `[a-z0-9]+(?:-[a-z0-9]+)*`；采用个人默认时还须有一个 `z-`，去掉前缀的主体最多 62 字符。**用户要求保留其他有效完整名称时，不运行必须以 `z-` 开头的断言。**

默认命名路径中的旧式下划线先转为单连字符，再处理大小写、连续连字符和重复前缀，核对主体非空与总长。不保留下划线格式例外；明确要求原样保留的无效名称先说明问题，不静默改写。

例如基础名 `release_note_helper` → `z-release-note-helper`；已有 `z-release-note-helper` 不再加前缀；“完整名 `team-guide`，原样保留” → `team-guide`。名称规范化后先检测目标冲突。

## 引用与 UI

- 目录名、frontmatter `name`、安装目标、README 调用名与 `$skill-name` 必须使用同一个最终名称。
- 创建 UI metadata 时，`display_name` 保留 `z-` 个人筛选前缀且不重复，`default_prompt` 引用真实调用名。显示名不是调用标识：精确保留 `team-guide` 时可显示 `z-Team Guide`，调用仍是 `$team-guide`；用户另有明确 UI 要求时尊重。
- 维护已有 metadata 时只改相关字段，不覆盖无关的策略、依赖或图标；自动发现策略不因涉及发布就擅自改为显式调用。
- README 解释实际采用的命名选择，不在精确保留其他名称时错误宣称该 skill 以 `z-` 命名。

## 冲突、安装与验证

同名文件、目录、软链接及断开的软链接都算已有目标。保护原件，不覆盖；改进用户指定的既有 skill 不等于创建冲突，按授权在原位修改。明确要求迁移时另核对新旧引用与安装冲突。

运行标准格式验证器核对名称、目录及 frontmatter，不修改验证器放行错误。再用真实目标客户端按最终名称发现、加载并完成代表性任务；格式、安装、发现与行为分别记录，不以其中一项代替其余项。其他客户端只声明实际测过的范围。
